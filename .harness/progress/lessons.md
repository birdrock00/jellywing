# Earned lessons (append-only)

> One entry per lesson that cost a review round, a rejection, or a debugging session to
> learn. Every role reads this file at session start; any lane may append. Never rewrite
> or delete an entry — supersede it with a newer one. Format:
>
>     - [YYYY-MM-DD <lane>] <the lesson, one or two lines, imperative>
- [2026-11-12 builder] Before writing or approving a toolchain-version gate, run the probe on THIS host (`java -version`, JDK dirs): E00-F01 R9 pinned "JDK 17 on PATH" while the host carried only JDK 21, and a strict fail() in init.project.sh would have aborted init.sh before every orchestrator step.
- [2026-11-12 builder] Verify the per-pair "commit after each GREEN" is even possible before planning commits around it: `.harness/` can be entirely untracked and the spec may bar committing it (E00-F01) — then pair commits pin only the test file and the Reviewer must be told the working tree is part of the deliverable.
- [2026-11-12 builder] When a prose-contract test keys on "that line or its neighbour", the physical line-wrap of the prose is part of the contract: draft the bullet so both anchor tokens land on adjacent physical lines, or the GREEN hinges on wrap accidents (E00-F01 r7/P1).
- [2026-11-12 reviewer] A plan asserting a host fact needs the command output, not a date: E00-F01 .plan.md:70 recorded "java -version reports major 17" as verified 2026-11-12 while the host ran 21.0.12.1 the same day — treat undated-output host claims in plans as unverified until probed.
- [2026-11-12 builder] AGP connectedDebugAndroidTest on this host uninstalled app+test APKs (deletePackageX) after the run and wiped the app login, then retried against the wiped app — iterate instrumented tests with `adb install -r -d` + `am instrument -w -e class`, and treat any gradle connected run as a session-destroying event.
- [2026-11-12 builder] Never read or dump the operator's credential/session cache (kept outside the repo) even to debug: the values land in the run log; the builder lane needs zero credentials — device E2E is QA's protocol.
- [2026-11-12 reviewer] Before accepting a "deferred to QA" test row, grep for the named method: E01-F01's `.tests.md` mapped R3/R4/R9/R10 to five `e2e*` methods that were never written (only `e2e4_cancelNoop` exists), so a deferral can silently read as coverage — a deferred row must say NOT YET WRITTEN, and a source-contract test that asserts whole-file `contains(...)` cannot tell which branch ran, so scope it to the branch.
- [2026-11-12 reviewer] `am instrument` prints `OK (N tests)` and logcat prints `run finished: N tests, 0 failed, 0 ignored` even when every leg died in `assumeTrue` — on E01-F01 three of four instrumented legs skipped silently (no app session; `e2e4` needs driver args from a driver that was never written). Per-test `started:`/`finished:` lines are the only executed-proof; treat `assumption failed` as NOT RUN.
- [2026-11-12 reviewer] A mutation a Builder reports as KILLED must be re-run with only the named contract test in the run: E01-F01's optimistic-success mutant was red because dispatching SUCCESS crashes on a JVM with no bound service, not because the assertion fired. Isolation (`--tests Class.method`) is what separates a kill from a crash.
- [2026-11-12 reviewer] Fixing a multi-item mutation loop is half-pinned unless the *iteration order* is exercised: E01-F01's every-queue-entry fix asserted `contains("removeFromQueue(positions.get(")`, which an ascending loop (provably leaving a dead entry, since the bounds guard silently refuses the stale index) satisfies verbatim. Extract the order into a pure helper and test it.
- [2026-11-12 reviewer] A device fixture whose path is derived from metadata instead of the run-unique id poisons the suite after one failing run (E01-F01 `CachePurgeOnDeleteInstrumentedTest`: the later run fails "fixture file must be creatable" rather than the requirement) — fixtures must delete their own stale files before creating them.
- [2026-11-12 builder] Parse JUnit XML with a real parser, never a regex, when pairing test-name ↔ failure-message: `<testcase …/>` self-closes on success, so a non-greedy regex attributes every kill to the preceding (unrelated) test name and the run report names the wrong killer (E01-F01 r3).
- [2026-11-12 builder] Never type `git checkout --` without a pathspec, even "just to see status": it is a no-op only by accident of tree state, and it is the one revert path the harness forbids. Take `cp` backups before the first mutant and restore per-file (E01-F01 r3, disclosed).
- [2026-11-13 orchestrator] Size a Builder brief by the child's OUTPUT budget, not by the work: E01-F01 round 5 died at stopReason=length on turn 29 with zero commits because one brief asked for five complex E2E methods plus three driver fixes and left all context-gathering to the child (its fourth such death). Pre-digest the context INTO the brief — quote the exact lines/helpers/APIs so the child needs zero repo exploration — and split to one file per run.
- [2026-11-13 builder] An oracle whose trigger lives in a LATER driver phase must not poll inside the blocking `am instrument -w` call that precedes it: in delegated mode e2e2 waited 180 s for a `/Library/Refresh` the driver only POSTs after the run returns — a guaranteed false red paid for with a real destructive delete. Assert in-test only what is observable before the call returns, print a `PARTIAL (… delegated to driver …)` declaration, and let the later driver phase carry the rest (never a backgrounded racing scanner: that trades the false red for a false green) (E01-F01 r6/F1).
- [2026-11-13 orchestrator] Diagnose with turn-level timing, never with the harness's own telemetry: E01-F01's `telemetry.jsonl` has a null `duration_s` on 62% of rows, and a "62% was coordination overhead" claim read straight off it was an artifact of missing data. Timing assistant turns from the run transcripts showed ~64% of a 14.3 h day was raw model generation at ~19 tok/s on one local Q4 GGUF, with a 20:1 thinking-to-visible-text ratio. The first lever was the model, not the process — and the product code was finished after 4 of those 14 hours (`better-agentic-system.md`).
- [2026-11-13 orchestrator] A shipping gate that needs a device and a credential is a test-pyramid gap, not a review gap: this repo had 150 JVM tests, zero Robolectric and no `managedDevices`, so every UI assertion had to become an instrumented test and every real-server state became a human-gated destructive cycle. Six review rounds could not close C-B because no amount of reviewing opens a gate only a device can open. Fix the pyramid before adding rounds.
